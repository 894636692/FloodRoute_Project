# C 组：站点与水位数据可用性阶段验收

本文件保留站点与水位阶段的验收快照。随后已新增降雨来源核查及历史候选解析，最新整体进度以 [C 运行说明](c_dynamic_runbook.md)、[降雨核查](rainfall_source_check_2026-09-18.md)和数据清单为准；动态模块测试现为 16 项。下文“8 项测试”“降雨尚未核验”描述的是当时阶段状态。

**结论：真实数据已取得，站点和水位中间表已验收；最终动态接口仍为 blocked。** 本阶段完成了“能否取得及解析样本”的核查，但没有完成第一阶段要求的真实 stations.csv 加 water_level.csv/rainfall.csv 交付，也没有完成 API 运行验收。

范围为当前下载快照，不把站点数量当作深圳全部现役站点数量，不把目录上架日期当作最早观测时间。

## 清单中的两个状态

[dynamic_data_inventory.csv](dynamic_data_inventory.csv) 保留用户要求的 16 个字段，并增加三个用于定位中间成果的字段：

- processing_stage：stations、water_level 为 interim_ready，表示中间处理与核验完成；rainfall、forecast_ensemble 仍为 not_checked。
- interim_path：实际中间 CSV 路径。
- quality_report_path：对应质量报告路径。

原有 status 表示最终接口状态，站点和水位继续 blocked。unit 记录源单位，水位仍为 m；中间表已转换为 cm，记录于 notes 及质量报告。time_start/time_end 继续留空，因为尚不能填写有明确时区的范围。

## B 组接入差距

已读取当前 `src/floodroute/common/schema.py`、`src/floodroute/risk/models.py` 和 `docs/b_routing_interface.md`，不是依据旧版本推断。

| B 当前要求 | 中间表现状 | 接入前需要什么 |
|---|---|---|
| station_id、source、water_level_cm、quality_flag | 已有，但包含待确认质量标记 | 共同约定可接受的质量状态及重复处理规则 |
| timestamp | 只有 source_time_without_timezone | 官方明确时间语义和时区，再转换为带 +08:00 的时间 |
| lon、lat | 水位表无这两列，站点表为空 | 合法取得站点坐标并确认 CRS；与 A/B 协调空间接口 |
| retrieved_at | 列存在但为空 | 该历史下载批次的可靠获取时间证据，或后续采集时明确记录；不得使用 processed_at 代替 |

B 当前代码要求 timestamp 带时区，并把经纬度作为 EPSG:4326 点位参与空间匹配。因此“补列名”不能解决语义和坐标缺失。中间表不得复制为 B 的正式输入。本步未修改 B 的实现。

`data/derived/dynamic/water_level.csv`、`rainfall.csv` 仍是 source=fixture 的旧联调样例；真实 stations.csv 尚未生成。清单的 derived_path 对 stations 是规划路径，对水位/降雨是未来拟替换的接口路径，不意味着对应真实接口已交付。

## 阻塞项与可继续方向

| 缺什么 | 为什么缺 | 可推进的动作及边界 |
|---|---|---|
| 坐标及 CRS | 名录不公开坐标 | 向提供方确认是否存在合规研究申请或可公开的替代空间信息；可与 A 讨论已有合法来源，不按站名猜坐标 |
| 时间语义、时区、水位零点 | 已取得元数据和 API 说明未定义 | 使用[咨询草稿](dynamic_metadata_questions_2026-09-18.md)向提供方核实；尚未发送 |
| 下载获取时刻 | 原文件未包含可靠获取时间记录 | 不为本批次补造时间；今后采集应在取得响应/文件时记录批次获取时间 |
| 更长历史及完整性 | 当前只有一个快照；文件导出限制未明确 | 官方说明或获得权限后的少量分页、日期测试；API 不是本地清洗的前提 |

在这些问题解决前，已有中间表可用于非空间的数据检查与接口设计讨论。后续可单独开展“真实实况降雨来源可用性核验”，从是否可获取、坐标/CRS、时区、累计时段是否明确开始；目前没有选定或验证替代来源，不宣称它能替代积水深度。

本阶段没有人为制造延迟、降低水位、使用未来数据判断当前风险，未进行 Ground Truth/Observed 场景划分。第一天的可用性核查已形成明确结论；完整第一阶段交付仍未达标，后续应补证或调整数据源，而不是将 blocked 改写为 validated。
