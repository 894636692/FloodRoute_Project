## 建议检查顺序

1. 浏览器缩放100%，分别采用上述三种窗口尺寸。标题不异常折行、主内容无水平滚动、地图不溢出，开始规划完整可见，侧栏控件可正常操作。
2. 先在线选起点，再切换模式选终点。地图保持原视角，蓝/橙标记分别更新；侧栏显示“✓ 已选择并吸附至道路”和吸附距离。普通状态不显示内部节点编号。
3. 点击开始规划，确认路线成为主要视觉内容、起终点及全路线都在视野内且有边距。确认距离如“5.25 km”、预计行程如“10.9 分钟”、状态“单次规划”完整显示（具体数值由选点决定）。
4. 手动平移/缩放地图，再选新点：视角保持、旧结果标为需重新规划、不自动执行算法；再次规划后重新聚焦。重复事件和模式切换不得把旧点误设为新点。
5. 切换离线模式，确认没有在线瓦片、轻量道路背景与在线地图明显不同。真实场景明确“本时次真实降雨较弱，主要用于验证真实动态数据链路。”；模拟场景明确不代表历史实测。
6. 模拟回放确认17时次逐帧播放、固定同一组起终点、路线变化时聚焦，完成后可继续选点和规划。

## 2026-09-21 v1.2 自动化证据

这些结果来自 Codex 内置 Chromium 的实际控件和地图交互，只是可复查的自动化证据，不替用户勾选上面的人工清单。

- “查看信息”可在任意位置查询；实际显示格网 1229、近1小时累计降雨 0.0 mm、数据时间/来源，以及最近正式道路的高程、坡度、土地覆盖与当前风险组成。未知道路名显示“暂无可靠数据”，真实水位只显示“未启用”。
- 降雨层收到 4,232 个轻量值，道路风险层收到 26,254 个轻量值；静态 geometry 各加载一次。开启、关闭和再次开启后 `mapInstanceId` 不变，路线 pane 位于两种数据层之上。
- 真实点击得到道路最近点，浏览器实测示例吸附距离为 15 米、73 米和 8 米；超阈值点击没有产生终点，随后合法点击正常完成选择。
- 三档视口的页面 `scrollWidth` 均等于视口宽度。路线结果完整显示 `2.25 km / 0.340 / 0.845 / 1.000 / 0.155 / 4.7 分钟 / 单次规划`，没有省略号。
- 全部 105 项测试通过（37.606 秒）。浏览器性能样本见 [UI 性能报告](UI_PERFORMANCE_REPORT.md) 和 [v2 JSON](../results/ui_end_to_end_performance_v2.json)。

## 自动化证据的边界

### 2026-09-20 内置浏览器实际交互复验

浏览器：Codex In-app Browser；页面：http://127.0.0.1:8502/。这些是代理通过页面控件和地图点击取得的结果，不替用户勾选上面的人工检查表。

- 起点点击经纬度 114.041862, 22.539196，吸附距离 67.2 米；终点 114.069328, 22.551879，吸附距离 32.5 米。侧栏状态与详细信息折叠面板可正常读取。
- 两点选择完成前规划按钮不可用；选点本身没有生成路线。点击开始规划后，真实场景结果为 7.73 km、16.1 分钟、单次规划，七项指标完整可见。
- 地图从研究区视角自动缩至路线附近（比例尺从 3 km 变为 500 m）；蓝色起点、橙色终点与绿色完整路线均可见，周围留有空间。在线 OSM 瓦片与版权署名可见；离线为灰色道路背景，两者明显不同。
- 分别设置 1366×768、1600×900、1920×1080 的浏览器视口并查看截图。页面 scrollWidth 等于视口宽度，七项指标 scrollWidth 等于 clientWidth，未发现指标截断或页面横向溢出；标题、副标题正常，开始规划可见，侧栏可纵向滚动。地图 iframe 高度 560px。这里验证的是视口尺寸，不是三台物理显示器或 Chrome 窗口。
- 真实场景保留弱降雨说明；模拟场景明确“不代表历史实测”。切换场景后提示旧结果需要重新规划，旧路线隐藏。
- 动态回放实际运行并观察到 12:45 中间状态和 16:00 最后时次；完成后仍可交换起终点和重新规划。未逐帧保存全部17帧画面。
- 发现并修复：交换起终点导致组件重建时，地图曾退回研究区。现在旧结果失效期间恢复保存的中心与缩放，新规划仍由路线 fit bounds 控制。修复后重复交换，比例尺保持 500 m，旧结果提示仍正确；反向重新规划显示 7.02 km、14.6 分钟。
- 最终重新运行全部测试：96 项通过，36.285 秒。日志：`work/ui_e2e_regression_tests.log`。未改算法、参数、真实数据或实验结果。

### 2026-09-20 浏览器端到端性能验收

使用 Codex In-app Browser（Chromium）和浏览器 `performance.now()` 完成 3 次冷启动、10 次起点点击、10 次终点点击与 10 次规划。优化后页面外壳中位数 318.8 ms、地图可点击 2257.0 ms、起点 marker 266.3 ms、终点 marker 250.2 ms、路线与指标 309.8 ms；全部达到本轮目标。30 次热交互均保持同一个 iframe、document、Leaflet map 和地图容器，`full_map_remount = false`。在线 OSM 21 张瓦片禁用缓存时 335.5 ms 完成，并与 marker/route 更新解耦。详情及全部样本统计见 [性能报告](UI_PERFORMANCE_REPORT.md) 和 [JSON证据](../results/ui_end_to_end_performance.json)。
