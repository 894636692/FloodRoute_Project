# 测站基本信息下载验收记录

核验日期：2026-09-18。本步只检查已下载原始文件，不清洗或覆盖原件，不生成带坐标的最终接口。

数据集为深圳市水务局提供的[市水务局测站基本信息表](https://opendata.sz.gov.cn/data/dataSet/toDataDetails/29200_01400987)，资源编号 `29200/01400987`。来源信息可在下载包内 RDF 元数据和 XLSX「资源描述信息」工作表核对。

原始文件位于 `data/raw/dynamic/stations/`：

- `市水务局测站基本信息表20260918114804559062.zip`，52,543 字节，包含 CSV、JSON、XLSX、XML、RDF 五种导出格式。
- `市水务局测站基本信息表_2920001400987.json`，40,164 字节。
- 与 ZIP 同名的已有解压目录，包含上述五个文件。

ZIP 完整性检查通过。五个已解压文件均与 ZIP 对应成员逐字节一致；根目录 JSON、ZIP 内 JSON、解压目录 JSON 也逐字节一致，SHA256 均为 `87b26d66fef9ac07817f0a19801b313cb87f31d67016820fbb8514204d779715`。

## 这份快照实际包含什么

CSV 只有三列：`测站编码`、`测站名称`、`站类`，分别对应 JSON/XML 的 `STCD`、`STNM`、`STTP`。

| 检查项 | 结果 |
| --- | --- |
| 下载快照记录数 | 485 |
| 唯一测站编码数 | 485 |
| 重复测站编码数 | 0 |
| 三列空值记录数 | 0 |
| 内涝水情站 | 148 |
| 河道水位站 | 133 |
| 水库水位站 | 204 |

485 是本次下载快照中的站点数，不能据此断言这是全深圳当前全部站点。三个站类的含义不同，不能把所有记录都当成积涝站。

名称存在两个重复组，共涉及四条记录：`梅林水库`、`石狗公水库`。因此名称不能作为关联键；后续与水位表关联应先核验测站编码是否对应。编码按字符串保存，避免把数字样式编码或含字母的编码错误转换为数值。

## 坐标与空间接口的阻塞原因

XLSX「资源描述信息」的摘要和 RDF 的 `dc:description` 均明确说明：

> 测站经纬度坐标信息属于保密资料不宜向社会公开

这份下载没有经纬度字段，也没有坐标系声明。当前标记为 `coordinate_crs_unknown`；无法检查坐标是否合法、是否超出深圳范围，不能宣称坐标已统一为 EPSG:4326。站名不能代替官方坐标，不能填入猜测坐标来生成合格的 `data/derived/dynamic/stations.csv`。

## 格式核验与时间语义

JSON 原件的整体结构是 `{[...]}`，不是合法 JSON，直接使用 `json.loads` 会报错。本次仅在内存中去掉最外层多余花括号，以比较不同导出格式，未修改或保存回原始文件。

CSV、XML、XLSX 三种格式包含的记录一致；内存诊断读取的 JSON 记录也一致。RDF 记录顺序不同，按测站编码比较后内容一致。可以优先使用有效的 UTF-8 CSV 作为后续解析输入，不必改写有格式问题的 JSON 原件。

XLSX 的工作表维度声明有问题，`openpyxl` 默认只读模式可能只读出一行一列；正常载入且不保存可读到完整内容。「数据集1」为 486 行（含表头）、3 列，另有「资源描述信息」工作表。此读取差异不代表原始数据只有一条。

该表是测站基本信息，不是观测时间序列；没有观测时间戳、水位数值或水位单位。RDF 的 `updatedate=2024-06-27` 是资源元数据日期，不能当成水位观测时间，也不能由下载文件名推断观测时刻。

RDF 更新频率写作「不定期」，XLSX 写作「有数据更新时」，均是该站点信息数据集的说明，不能移用于水位数据的观测频率。历史水位范围、时区、单位仍需核验另一个数据集。

原始文件已取得，表格结构、记录数与编号检查通过；带坐标标准站点接口仍为 `blocked`，原因是经纬度不公开且 CRS 未知。这两个结论需要分开记录，不能将下载成功写成最终接口验收通过。
